# ADR-0003: First-party authentication with TOTP MFA

**Status:** accepted (Milestone 1)

**Context.** Admins create every account; there is no public sign-up. Privileged users (Super Admin, Management, Branch Manager, HR, Finance) need MFA. Deactivating an employee must cut off access immediately on web and mobile.

**Decision.**
* Passwords hashed with scrypt (N=16384, r=8, p=1, per-user salt). Minimum 10 characters with letters and numbers.
* Access token: HS256 JWT, 15 minutes, carries only user id, session id and organisation id. Permissions are loaded from the database on every request.
* Refresh token: 256-bit opaque value, stored as SHA-256 hash, rotated on every refresh, 30-day lifetime, revocable per device.
* MFA: RFC 6238 TOTP (any authenticator app). Secret encrypted with AES-256-GCM (`DATA_ENCRYPTION_KEY`). With `MFA_ENFORCEMENT=on`, privileged users who have not enrolled lose all sensitive permissions until they do.
* Lockout: 5 failed attempts → 15-minute lock. Per-IP+email rate limit on login and reset endpoints.
* Invitations and password resets: single-use hashed tokens (72 h and 1 h), no account enumeration.

**Alternatives.** Firebase Auth or an OIDC provider (Google Workspace, Microsoft Entra) can be added later behind the same `/auth` contract; the session and permission model does not change.

**Consequences.** We own security-critical code, so it is covered by integration tests (`apps/api/test/auth.test.ts`) and must be part of the pre-launch security review.
